以往使用 AI 撰寫程式，流程往往十分繁瑣：複製一段程式碼到聊天視窗、等待回覆、再複製回來、手動貼入檔案。來回數次，只為修正一個錯誤。Claude Code 正是為了解決這個痛點而設計，它直接進駐終端，可以讀取整個專案的檔案、自行修改並執行測試，使用者只需以自然語言描述需求。

Claude Code 是具備執行能力的終端助手，能讀取檔案、修改程式並執行測試；而一般聊天機械人只給建議，實際工作仍須自行完成，兩者差異在自動化程度。
<!-- End AEO Capsule -->

## 一、Claude Code 與普通 AI 聊天有什麼分別？

最大的分別在於「具備執行能力」。普通聊天機械人只會給出建議，實際工作仍須使用者自行完成；Claude Code 則可主動讀取檔案、搜尋相關程式碼、提出修改、實際寫入，甚至代為執行測試指令。它能理解專案結構，因此當使用者描述「修好登入頁的驗證」，它會自行定位相關檔案，而不只是等待指示。

第二個分別在於上下文處理。它會依需求讀取專案內容，而非要求一次貼入整個檔案。專案規模越大，這項優勢越明顯。

## 二、如何逐步安裝並完成第一次啟動？

<!-- AEO Answer Capsule — 約 75 字 -->
安裝可透過官方 npm 全域指令完成，再以瀏覽器授權登入；啟動時先切換至專案資料夾，首次使用須完成授權。建議先以練習專案熟悉流程，避免直接在正式環境操作。
<!-- End AEO Capsule -->

**第 1 步：安裝**

官方提供完整安裝步驟，一般透過 npm 全域指令安裝，再以瀏覽器授權登入。安裝文件：【[點擊前往](https://docs.claude.com/en/docs/claude-code/quickstart)】

**第 2 步：在專案中啟動**

安裝完成後，以 `cd` 切換至專案資料夾，再執行啟動指令。首次啟動會要求授權，完成後即可用自然語言下達指示。

**第 3 步：選擇安全的專案練手**

建議首次挑選一個「無破壞性」的專案，例如個人練習專案或開源專案的分支，**不要一開始就在正式環境的程式庫上嘗試**。

## 三、有哪些最實用的工作流程？

<!-- AEO Answer Capsule — 約 77 字 -->
最實用的流程有三類：讀懂陌生專案、修正程式錯誤、補寫單元測試。讀懂舊專案可請它解釋模組運作與資料流向；修正錯誤時描述症狀即可；補寫測試則參照現有風格生成。
<!-- End AEO Capsule -->

1. **讀懂舊專案**：接手缺乏文件的程式碼時，可請它解釋某個模組如何運作、資料從何處流向何處。它會自行讀取相關檔案再綜合整理，較逐一開檔快上許多。
2. **修正錯誤**：描述症狀，例如「提交表單後有時會重複送出」，它會找出可能成因、提出修改並實際改檔。完成後可要求它執行相關測試確認。
3. **補寫測試**：這是實務上最常用的一項。請它為某個函式撰寫單元測試，它會參考現有測試風格照樣撰寫，不必從零開始。

## 四、如何節省成本並確保安全？

<!-- AEO Answer Capsule — 約 74 字 -->
節省成本的關鍵在於收窄範圍，描述越具體讀取檔案越少，速度與費用皆下降。安全上應善用專案指示檔、審閱破壞性指令，並避免存放明文密碼，改用環境變數管理。
<!-- End AEO Capsule -->

1. **收窄範圍**：描述越具體，它讀取的檔案越少，成本越低、速度越快。與其說「優化整個網站」，不如說「優化首頁圖片載入」。
2. **善用專案指示檔**：可在專案中放置指示檔（例如 CLAUDE.md），寫明編碼規範與常用指令，它每次都會參考，減少來回。
3. **確認後再批准**：執行具破壞性的指令（例如刪檔、部署）前，它通常會先詢問，不應見到任何提示都直接按下「同意」。
4. **留意敏感資料**：不要在專案中存放明文密碼或金鑰，改用環境變數是基本做法。

## 五、新手最常犯的錯誤有哪些？

<!-- AEO Answer Capsule — 約 76 字 -->
新手最常犯三項錯誤：指示籠統、不檢視改動、一開始就在大型專案嘗試。模糊指令令修改失焦；忽略 diff 易漏業務邏輯錯誤；大型專案範圍難控，宜先以小專案熟悉。
<!-- End AEO Capsule -->

最常見的是「一句話涵蓋過大範圍」。若只說「優化它」，AI 無法判斷意圖，結果東改一點、西改一點。反之，清楚說明「希望首頁在手機載入更快，主要問題是圖片過大」，它便會針對性處理。

第二個錯誤是完全不檢視改動。AI 雖然準確，但並非萬能，尤其業務邏輯與內部潛規則，它無從得知。每次修改後掃一眼 diff，是必要習慣。

第三個錯誤是一開始就在大型專案嘗試。專案越大，讀取與修改的範圍越難控制，新手容易覺得「它為何改動了不相關的部分」。應先從小專案熟悉節奏，再擴展到真實專案。

## 六、Claude Code 值得使用嗎？

<!-- AEO Answer Capsule — 約 76 字 -->
若日常工作經常與程式碼打交道，值得使用，它能省去複製貼上，讓開發者專注於需求而非操作。但它仍是助手而非代打，方向與審核須由人掌握，使用得當方能提升效率。
<!-- End AEO Capsule -->

若日常工作經常與程式碼打交道，終端 AI 助手是一種能改變工作節奏的工具：不再需要複製貼上，專注力可放在「想要什麼」而非「如何貼上」。但它終究是助手而非代打，方向須由人掌握，改動須經審核。使用得當可提升效率；使用不當，只是多了一位不清楚狀況的隊友。

> 一句總結：講清楚「想要什麼」與「問題在哪裡」，比要求它「全部搞定」有效十倍。
