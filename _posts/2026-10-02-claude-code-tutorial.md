以前用 AI 寫程式，流程係咁：複製一段 code 去聊天視窗、等佢回、再複製返嚟、自己貼入檔案。一來一回，改一個 bug 要貼十次。Claude Code 想解決嘅就係呢件事：佢直接住喺你嘅終端，可以讀你成個專案嘅檔案、自己改、自己跑測試，你只用講你想要咩。

## 佢同普通 AI 聊天有咩分別？

最大分別係「有手有腳」。普通聊天機械人只識講，你要自己做；Claude Code 可以主動讀取檔案、搵相關程式碼、提出修改、實際寫入，甚至幫你執行測試指令。佢亦理解專案結構，所以你講「修好登入頁嘅驗證」，佢會自己去搵相關檔案，而唔係要你指路。

第二個分別係上下文。佢會按需要讀取專案內容，而唔係要你成個檔案貼入去。你嘅專案越大，呢個優勢越明顯。

## 安裝同第一次啟動

安裝過程官方有完整步驟，一般係透過套件管理工具裝入指令，再用瀏覽器授權登入。裝好之後，喺你嘅專案資料夾入面啟動佢。第一次啟動佢會要求授權，跟住你就可以用自然語言落指示。

我建議第一次揀一個「無破壞性」嘅專案試手，例如一個你自己嘅練習專案或者開源專案嘅 fork，唔好一開始就喺生產環境嘅 codebase 上試。

## 三個最實用嘅工作流程

第一個係「讀懂舊專案」。當你接手一啲冇文件嘅程式碼，你可以叫佢解釋某個模組點運作、資料由邊度流去邊度。佢會自己讀相關檔案再綜合，比你自己逐個開檔快好多。

第二個係「修 bug」。你描述症狀，例如「提交表單之後有時會重複送出」，佢會搵出可能成因、提出修改、實際改檔。改完你可以要求佢跑相關測試確認。

第三個係「補測試」。呢個係我自己最常用嘅：叫佢為某個函式寫單元測試，佢會睇現有測試風格再跟住寫，唔使自己由零開始。

## 慳成本同保安全要注意咩

第一，範圍要收窄。你講得越具體，佢讀嘅檔案越少，成本越低亦越快。與其講「優化成個網站」，不如講「優化首頁圖片載入」。第二，善用專案內嘅指示檔。你可以放一個指示檔喺專案，寫低編碼規範、常用指令，佢每次都會參考，減少來回。第三，睇清楚先批准。佢要執行具破壞性嘅指令（例如刪檔、部署）之前，通常會問你，唔好見乜都按「同意」。

另外，敏感資料要小心。唔好喺專案放明文密碼或者金鑰，即使係 AI 工具都唔應該接觸到。用環境變數係基本做法。

## 新手最常犯嘅錯

最常見嘅係「一句過講到太大」。你只講三個字「優化佢」，AI 唔知你想點，結果東改一啲西改一啲。反而講清楚「我想首頁喺手機載入快啲，主要問題係圖片太大」，佢就會針對性處理。

第二個錯係完全唔睇改動。AI 雖然準，但唔係萬能，尤其係業務邏輯佢唔會知你公司嘅潛規則。每次改完掃一眼 diff，係必要習慣。

第三個錯係一開始就喺大專案試。專案越大，佢讀取同修改嘅範圍越難控制，新手會覺得「佢點解改咗啲唔相關嘅嘢」。由細專案熟習節奏，再放大到真實專案。

## 值唔值得用？

如果你每日都要同程式碼打交道，終端 AI 助手係一種會改變工作節奏嘅工具：唔再需要複製貼上，專注力可以擺喺「想要咩」而唔係「點樣貼」。但佢係助手唔係代打，方向要你把，改動要你審。用得啱，佢會令你做得快啲；用得唔啱，只係多咗一個唔知做緊咩嘅隊友。

> 一句總結：講清楚「你想點」同「問題喺邊」，比叫佢「幫我搞掂」有效十倍。
